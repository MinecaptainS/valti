# VALTI 本机调试器

调试器源码与公众测试站在同一仓库。服务只监听 `127.0.0.1`，没有公众调试页面，也不使用 GitHub 登录、密码或访问令牌。需要 Node.js 22 或更新版本，无需安装 npm 依赖。

## 启动

Windows：双击仓库根目录的 **start-debugger.cmd**，保持窗口打开，再在浏览器打开：

**http://127.0.0.1:4174/**

也可以在仓库根目录执行：

```sh
node tools/debugger/server.cjs
```

按 Ctrl+C 停止。端口被占用时可设置环境变量 `VALTI_DEBUG_PORT` 为其他端口，启动后的终端会显示实际地址。此地址只在运行服务的本机有效。

## 操作

1. **题目与权重**：修改题干、提示、四个选项与各维度加分；新增、删除、上下移动普通题和枪法专项。Q1 固定为位置题并保留在第一位。
2. **选手列表**：新增或删除选手，修改主副位置、队伍、指挥标签、代表英雄、原始描述与八维向量；参考雷达随数值更新。
3. **队伍**：新增和编辑队伍名称、缩写及颜色。仍有选手引用的队伍不能直接删除。
4. **分数配比**：调整基础分、抬分指数及枪法专项占比；枪法专项内部占比由题目的相对权重决定。
5. **试算与分布**：手动选择一份答卷，检查前五名与最终八维；运行 100–2000 份固定种子的随机答卷，查看选手覆盖率、命中率与各维均分。

输入停止约 0.8 秒后自动保存本机草稿。无效数据会显示错误并保留输入，不覆盖上一次有效草稿。可以导出 JSON 备份，也可以导入有效 JSON。导入不执行 JavaScript。

“打开答题预览”使用当前草稿，不会改写正式数据。预览也只在本机服务内提供。

点击 **写入本地数据**，才会备份当前 `data.js` 并更新它。此操作不会提交或推送 GitHub。“载入已写入数据”可放弃草稿并回到当前 `data.js` 的内容。

## 文件与版本

- `.valti-debug/draft.json`：本机草稿。
- `.valti-debug/backups/`：每次写入前的 `data.js` 备份。
- `.valti-debug/` 已被 Git 忽略，不进入仓库或网站发布包。
- 新配置带有 `datasetRevision`，不同配置的答题历史分开保存，避免用新题目重新解释旧答案。原配置的浏览器记录仍保留。
- 增加选手后，公众页面的人数、图鉴和分享卡自动更新，新选手会使用原始描述与位置解读。

若需恢复已写入之前的版本，先停止调试服务，把对应备份复制为仓库根目录的 `data.js`，再重新启动。

## 发布公众测试站

```sh
node scripts/package-public.cjs
```

仅发布生成的 **dist/** 目录。它只含 `index.html`、`styles.css`、`app.js`、`data.js`，不包含调试器、测试、草稿或备份。工具发现 dist/ 中有额外文件会停止，不会把它们混入发布包。

仓库依然公开，已经提交到仓库的源码与选手数据仍然公开；本机草稿、备份和服务访问是独立的。请不要把本机服务通过端口转发暴露到外网。
